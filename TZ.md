# Техническое задание на проект  
## **Pollen Tracker — сервис прогнозирования аллергенной пыльцы**

---

## 1. Цель проекта
Создание веб-сервиса для аллергиков, предоставляющего персонализированный прогноз концентрации аллергенной пыльцы в атмосфере.  
Система анализирует данные о пыльце, учитывает индивидуальные аллергии пользователей и генерирует рекомендации для снижения симптомов аллергии.

---

## 2. Роли пользователей

- **Зарегистрированный пользователь**
  - Просмотр персонализированных прогнозов пыльцы
  - Настройка профиля (аллергии, город)
  - Получение рекомендаций

- **Администратор**
  - Управление типами пыльцы
  - Управление рекомендациями
  - Управление данными через **Django Admin**

---

## 3. Модели данных (сущности)

### 3.1 UserProfile (Профиль пользователя)
**Назначение:** хранение дополнительной информации о пользователе  

**Поля:**
- `user` — OneToOne к стандартной `User`
- `age` — возраст
- `city` — город проживания
- `latitude`, `longitude` — координаты города
- `allergens` — ManyToMany к `PollenType` через `UserAllergy`

---

### 3.2 PollenType (Тип пыльцы)
**Назначение:** справочник типов аллергенной пыльцы  

**Поля:**
- `name` — название растения
- `openmeteo_code` — идентификатор для API
- `category` — дерево / трава / сорняк
- `allergenicity` — коэффициент аллергенности
- `color` — цвет для визуализации

---

### 3.3 PollenData (Данные о концентрации пыльцы)
**Назначение:** хранение данных о концентрации пыльцы  

**Поля:**
- `pollen_type` — FK к `PollenType`
- `city`, `latitude`, `longitude` — локация
- `date`, `hour` — время измерения
- `concentration` — концентрация (grains/m³)

---

### 3.4 UserAllergy (Аллергия пользователя)
**Назначение:** связь пользователя с типами пыльцы  

**Поля:**
- `user` — FK к `UserProfile`
- `pollen_type` — FK к `PollenType`
- `sensitivity` — уровень чувствительности

---

### 3.5 Recommendation (Рекомендации)
**Назначение:** хранение рекомендаций для аллергиков  

**Поля:**
- `category` — категория рекомендации
- `pollen_type` — FK к `PollenType` (опционально)
- `title` — заголовок рекомендации
- `text` — текст рекомендации

---

## 4. Ключевой функционал (User Stories)

### 4.1 Регистрация и настройка профиля
Пользователь регистрируется, указывает город проживания и возраст.  
В личном кабинете выбирает типы пыльцы, на которые у него аллергия.

---

### 4.2 Просмотр прогноза пыльцы
Авторизованный пользователь видит графики концентрации пыльцы за выбранный период:
- день
- неделя
- месяц  

Отображаются:
- только аллергены пользователя  
- либо все типы пыльцы (если аллергии не указаны)

---

### 4.3 Получение персонализированных рекомендаций
Система анализирует:
- текущую концентрацию пыльцы
- чувствительность пользователя  

И выдает рекомендации, например:  
> *«Сегодня высокий уровень пыльцы березы — ограничьте пребывание на улице»*

---

### 4.4 Прогнозирование на месяц
На основе исторических данных система строит прогноз концентрации пыльцы на месяц вперед, используя:
- статистические методы
- сезонные паттерны

---

### 4.5 Обновление данных через внешний API
Автоматическое обновление данных о концентрации пыльцы через **Open-Meteo API** для поддерживаемых городов.

---

## 5. Внешние интеграции и аналитика

### Внешние интеграции
- **Open-Meteo API** — получение актуальных данных о концентрации пыльцы
- **Django** — ORM, административная панель, система аутентификации

---

### Аналитика

**Библиотеки Python:**
- `pandas` — анализ исторических данных и прогнозирование
- `numpy` — статистические вычисления
- `openmeteo_requests` — работа с метеорологическим API

---

### Визуализация
- **Chart.js** — интерактивные графики на фронтенде
- Автоматическое построение графиков концентрации пыльцы
- Цветовая кодировка различных типов пыльцы

---

### Алгоритмические модули
- **Модуль прогнозирования**  
  Прогноз на месяц с учетом сезонных колебаний
- **Модуль оценки риска**  
  Расчет уровня риска на основе концентрации, аллергенности и чувствительности
- **Модуль рекомендаций**  
  Генерация персонализированных рекомендаций

---

## 6. Технический стек

- **Бэкенд:** Django 4.2.16, Python 3.13.5
- **База данных:**
  - SQLite — разработка
  - PostgreSQL — продакшен
- **Фронтенд:** HTML / CSS / JavaScript
- **Графики:** Chart.js
- **Аналитика:** Pandas, NumPy
- **API клиент:** Open-Meteo Python Client

---

## 7. Архитектурные решения

- **Модульная структура**  
  Отдельные приложения для:
  - моделей
  - API-интеграций
  - аналитики
  - визуализации

- **Сервис-ориентированный подход**  
  Отдельные модули для:
  - работы с внешним API
  - построения графиков
  - генерации рекомендаций

- **Панель администратора**  
  Полная настройка всех моделей через **Django Admin**

- **Управление командами**  
  Кастомные management-команды для:
  - обновления данных
  - заполнения БД
  - тестирования
